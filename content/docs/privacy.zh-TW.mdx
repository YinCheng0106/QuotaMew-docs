QuotaMew 的設計以本機處理與最小化資料存取為原則。

穩定版額度監控專注於 Provider 額度資訊與本機 App 狀態，不分析提示詞或程式內容。QuotaMew 無遙測、無廣告分析，也不出售使用者資料；這裡描述的是 App，不代表 Provider runtime 或所有你造訪的網站。

QuotaMew 需要存取部分 Provider 狀態資訊，才能顯示使用量與重置時間，但不代表 QuotaMew 會收集你的所有 Provider 資料。

<Callout type="info" title="以本機處理為主">

目前 QuotaMew 不需要 QuotaMew 帳號，也沒有自己的 Analytics、Cloud Sync 或 QuotaMew 雲端後端。

Provider 本身仍可能進行自己的網路通訊與驗證。

</Callout>

## QuotaMew 會存取哪些資訊？

### Codex

QuotaMew 會尋找本機可相容的 Codex runtime，並透過 Codex 提供的 runtime 介面取得使用額度與 Rate Limit 等必要資訊。

Codex 本身負責自己的登入、驗證與 Provider 通訊。

QuotaMew 不需要直接讀取或複製你的 Codex 驗證檔案。

QuotaMew 也不需要掃描你的 Codex Session 歷史或 Prompt 紀錄來取得額度資訊。

### Claude Code

Claude Code 支援目前仍屬於**實驗性／未驗證**。

目前的實作只讀取小型、具版本的 QuotaMew 本機 snapshot，不掃描 Claude Code 對話紀錄、提示詞歷史、憑證或內部使用量快取。

穩定版不會安裝或設定 snapshot 橋接，限制請見 [Providers](./providers.mdx)。

## QuotaMew 不會刻意收集哪些資料？

QuotaMew 的目前實作不會刻意收集或上傳：

- Prompt
- AI 對話內容
- 專案原始碼
- 程式開發歷史
- API Key 或登入憑證
- Provider Session 內容
- 完整 Provider 原始回應
- Repository 內容

這裡所描述的是 QuotaMew 自身的資料邊界。

Codex、Claude Code 或其他 Provider 仍有自己的資料處理與網路行為，應另外參考各 Provider 的官方隱私權政策。

## 本機設定

QuotaMew 會在你的 Mac 上儲存應用程式設定，例如：

- 是否啟用特定 Provider
- 通知設定
- 通知門檻
- 使用量顯示方式
- 固定顯示的 Provider
- 選單列顯示偏好
- Onboarding 狀態

這些設定用於維持 QuotaMew 的應用程式行為與使用者偏好。

這些偏好使用 macOS UserDefaults 儲存，不會透過 QuotaMew 雲端服務同步。

## 本機通知與重置狀態

設定不是唯一的本機資料。QuotaMew 也會保留有限的 App 狀態，用來避免重複通知，以及比較近期額度週期以判斷重置。這可能包含 Provider／額度視窗識別、重置與擷取時間、提醒標記及近期額度數值。它是本機功能所需的狀態，不是完整歷史分析紀錄，也不會上傳到雲端。

行為與送達限制請見[通知與重置提醒](./menu-bar.mdx#通知與重置提醒)。

## Diagnostics

QuotaMew 的 Diagnostics 功能設計為只輸出有限且經過篩選的診斷資訊，例如：

- QuotaMew 版本
- macOS 與系統資訊
- Provider 狀態
- Runtime 狀態
- Connection 狀態
- Refresh 狀態
- 部分 Metadata 是否可用

Diagnostics 的設計不應包含：

- 登入憑證
- API Key 或 Token
- Prompt
- Session 內容
- 專案資料
- 私人檔案路徑
- Provider 的完整原始回應
- 精確的私人使用內容

<Callout type="warn" title="分享 Diagnostics 前仍應先檢查內容">

即使 QuotaMew 的 Diagnostics 設計為 privacy-safe，在將任何診斷資訊公開貼到 GitHub Issue 或其他地方以前，仍建議先自行檢查內容。

請勿公開任何你認為敏感的資訊。

</Callout>

## 網路存取

QuotaMew 本身不需要 QuotaMew 帳號或自己的 Cloud Sync 服務。

當 QuotaMew 與 Codex 等 Provider runtime 互動時，Provider 本身可能會依照自己的設計進行網路通訊。

因此，不應將「QuotaMew 以本機處理為主」解讀為「執行 QuotaMew 時整個系統完全不會產生任何網路連線」。
